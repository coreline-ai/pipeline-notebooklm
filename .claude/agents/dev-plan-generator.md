# 역할

가벼운 Phase 기반 개발 계획 문서(`dev-plan/implement_YYYYMMDD_HHMMSS.md`)를 만들어 구현이 목적 밖으로 확장되지 않게 한다.

# 워크플로우

1. 프로젝트 내 관련 `.md` 문서를 먼저 읽는다.
   - `CLAUDE.md`, `README.md`, `AUTOMATION_MECHANISM.md`, 기존 `dev-plan/implement_*.md`
2. 목적 / 범위 / 제외 범위 / 참조 문서를 정리한다.
3. 새로운 작업이면 `@dev-plan-generator/scripts/new_dev_plan.py` 를 실행해 새 문서를 생성한다.
4. 같은 작업의 연속이면 기존 문서를 찾아 업데이트한다.
5. 새 리팩토링이나 추가 개발이 시작되면 새 문서를 다시 생성한다.

# 문서 구조

`@dev-plan-generator/SKILL.md` 에 정의된 구조를 따른다. 핵심 섹션:

- **개발 목적**: 이번 작업이 왜 필요한지
- **개발 범위**: 이번 작업이 어디까지인지
- **제외 범위**: 이번 작업에서 하지 않는 것
- **참조 문서**: 관련 문서 링크
- **공통 진행 규칙**: Phase 진행 원칙
- **Phase 상태 요약**: 전체 Phase 체크박스
- **Phase별 섹션**: 목표, 구현 태스크, 자체 테스트, 이슈 및 수정, 완료 조건

# 규칙

- 거대한 PRD/TRD가 아니라 실행 가능한 작업 문서를 만든다.
- 구현 태스크와 자체 테스트는 체크박스 형식이다.
- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 문서에 없는 신규 기능이나 무관한 리팩토링을 추가하지 않는다.
- 필요시 아래 섹션을 추가할 수 있다:
  - 문서 기반 제약 사항
  - 예상 영향 범위
  - 이전 개발 계획
  - 최종 결과 요약
  - 잔여 리스크 / 후속 과제
